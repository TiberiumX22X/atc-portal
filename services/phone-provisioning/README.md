# phone-provisioning

Сервис автопровижининга IP-телефонов Grandstream (GXP1610/1615/1620/1625, GXP2130/2140/2160/2170, GRP2613/2615/2636) для Asterisk/FreePBX. Написан для миграции с проприетарной АТС (Yeastar) на Asterisk, когда штатный механизм автонастройки телефона привязан к старой станции и заменить его нечем.

Раздаёт конфиги по HTTP (`cfg<MAC>.xml`), автоматически подставляет номер/пароль/имя из БД FreePBX, поддерживает 2 SIP-линии на устройство, раздачу прошивок, и массовую перезагрузку парка телефонов через встроенный веб-API Grandstream.

## Возможности

- Автопровижининг по DHCP option 66 или ручной настройке Config Server Path на телефоне
- Веб-админка: список устройств, карточка устройства (2 линии, BLF-клавиши), настройки по семействам моделей, раздел "Прошивки", импорт из xlsx/CSV
- Автоподстановка имени/пароля SIP-аккаунта по номеру из БД FreePBX (MySQL) — не нужно вручную вбивать пароли для всего парка
- Раздача прошивок с проверкой размера файла и защитой от скачивания деактивированными устройствами
- Массовая перезагрузка телефонов пачками (встроенный Grandstream Action URI reboot API), с настраиваемой паузой между устройствами
- 2 аварийных рубильника ("раздача конфигов"/"раздача прошивок" выкл/вкл) — на случай проблем во время миграции, когда старая и новая станции работают параллельно
- Активация/деактивация конкретных устройств — можно держать весь парк выключенным по умолчанию и включать точечно то, что реально тестируете

## Установка

```bash
git clone <URL этого репозитория>
cd phone-provisioning
sudo ./install.sh
```

Скрипт создаёт `/opt/phone-provisioning`, venv, systemd-юнит `phone-provisioning.service` на порту 8090 (переопределяется переменной `PROVISIONING_PORT`), и генерирует случайный пароль администратора для каждого семейства моделей (сохраните пароли, которые скрипт выведет на экран — они также видны позже в Настройках).

**После установки обязательно** зайдите в админку (`http://<сервер>:8090/admin/devices`) → Настройки → каждая вкладка семейства моделей → укажите реальный SIP-сервер/порт и NTP-сервер вашей сети (по умолчанию стоит заглушка `192.168.1.100`).

Удаление: `sudo ./uninstall.sh`.

## Как это работает

1. Телефон при сбросе к заводским настройкам получает по DHCP option 66 (или из ручной настройки) адрес `http://<сервер>:8090`
2. Запрашивает `cfg<MAC>.xml` — сервис ищет устройство в БД по MAC, подбирает шаблон под модель, рендерит конфиг (SIP-аккаунт(ы), NTP, язык, дата/время, прошивка)
3. Конфиги для всех трёх линеек моделей — в формате P-value (`<P123>значение</P123>`), а не более новом item/part — на части прошивок GRP-линейки item/part ненадёжно парсил поля с пароля со спецсимволами (см. `templates/grp2613_2615_2636.xml.j2` для деталей находки)
4. Телефон регистрируется в Asterisk уже с полученными данными

## Известные ограничения

- P-value номер для переключателя Wi-Fi на GRP2615/2636 не найден (был доступен только через устаревший item/part-параметр `network.wifi.enable`) — переключатель в интерфейсе Характеристик пока не действует на этих моделях
- Массовая перезагрузка полагается на нестандартный веб-API Grandstream (Action URI) — нужно, чтобы телефон уже получил конфиг с включённой этой настройкой хотя бы раз; при самой первой волне перезагрузки часть телефонов может запросить физическое подтверждение на экране

## Структура проекта

```
app.py                     — вся логика (Flask)
schema.sql                 — схема SQLite + дефолтные настройки
templates/*.xml.j2         — P-value шаблоны конфигов по семействам моделей
admin_templates/*.html     — веб-админка
install.sh / uninstall.sh  — установка и удаление (systemd, venv)
```
