# SSO Auth — единый вход для панелей АТС

Центральный сервис авторизации и портал-обёртка для проекта миграции
Yeastar K2 → Asterisk/FreePBX. Заменяет пять отдельных логинов
(confbridge-panel, phone-provisioning, alert-panel, cdr-panel,
monitor-panel) одним входом с общими ролями admin/operator.

Модуль "Обслуживание"/AMI-панель в портал пока не включён — оставлен
на будущее.

## Архитектура

```
nginx (порт 80)
 ├─ /            → sso-auth :8080 (портал, логин, пользователи)
 ├─ /_verify     → sso-auth :8080/_verify (internal, для auth_request)
 ├─ /monitor/    → auth_request + monitor-panel :8093 (доверенный заголовок)
 ├─ /conf/       → confbridge-panel :5000        (пока свой логин)
 ├─ /provision/  → phone-provisioning :8090      (пока свой логин)
 ├─ /alert/      → alert-panel :8091             (пока свой логин)
 └─ /cdr/        → cdr-panel :8092               (пока свой логин)
```

sso-auth и все панели слушают только `127.0.0.1` — наружу торчит
исключительно nginx. Панели, ещё не переведённые на SSO, продолжают
работать как раньше со своим логином через тот же nginx-проброс.

## Установка

```bash
sudo ./install.sh --install
```

Затем открыть `http://<сервер>/setup` и создать первого администратора.

Настроить nginx: взять `nginx/portal.conf` за основу, подставить свой
`server_name`/TLS при необходимости.

## Перенос существующих пользователей

Если в старых панелях уже есть логины (например `admin` в cdr-panel,
переименованный из `cdrpanel`), перенесите их одной командой **до**
первого захода на `/setup` — тогда `/setup` не появится, а найденные
пользователи уже будут в системе:

```bash
cd /opt/sso-auth
./venv/bin/python migrate_users.py --dry-run   # посмотреть, что перенесётся
./venv/bin/python migrate_users.py             # выполнить
```

Пароли переносятся как есть (хеши совместимы), логины не меняются.
При совпадении логина в двух панелях — первый найденный побеждает,
остальные пропускаются с предупреждением (разрешить вручную через
страницу «Пользователи»).

## План миграции панелей на SSO (по одной за раз)

Уже сделано:
1. **Monitor АТС** — переведена (см. `nginx/portal.conf`, блок `/monitor/`)

Для каждой следующей панели нужно:
1. В `config.py` панели сменить `HOST = "0.0.0.0"` → `HOST = "127.0.0.1"`
   (иначе SSO можно обойти, обратившись на порт панели напрямую)
2. В `auth.py` панели заменить проверку `session.get("username")` в
   `login_required`/`admin_required` на доверие заголовку
   `X-Remote-User`/`X-Remote-Role`, который подставляет nginx
   (см. как это устроено в `app.py` этого сервиса, эндпоинт `/_verify`)
3. Убрать/оставить как fallback собственную страницу логина панели —
   решить по панели (проще всего просто убрать, раз вход теперь только
   через портал)
4. Раскомментировать соответствующий блок `location` в `nginx/portal.conf`
   и добавить в него `auth_request /_verify;` по образцу `/monitor/`
5. Проверить, что старая cookie-сессия панели (`SESSION_COOKIE_NAME`)
   больше не нужна — можно убрать соответствующие настройки

Порядок оставшихся панелей — на ваше усмотрение, они независимы друг
от друга.

## Роли

- `admin` — управление пользователями портала + все административные
  функции внутри каждой панели (как и раньше в каждой панели по
  отдельности)
- `operator` — обычный доступ, без управления пользователями

Роль хранится в одном месте (`sso.db`), поэтому после миграции панели
на SSO её собственная таблица ролей/пользователей становится
неиспользуемой (можно оставить в БД панели как есть — она просто
перестаёт читаться).
