# CDR-панель

Журнал звонков и записей разговоров — читает `asteriskcdrdb.cdr` напрямую
(read-only), без AMI. Аналог экрана "CDR и записи" Yeastar K2.

## Установка

```bash
sudo ./install.sh --install
```
или запустить без флага и выбрать пункт 1 в меню.

Скрипт сам:
- создаёт `/opt/cdr-panel`, виртуальное окружение, ставит зависимости
- создаёт read-only MySQL-пользователя `cdrpanel` со случайным паролем
  (права только `SELECT` на `asteriskcdrdb`)
- регистрирует systemd-сервис `cdr-panel` на порту **8092**

После установки откройте `http://<IP-сервера>:8092/` — при первом заходе
будет предложено создать администратора (форма `/setup`).

## Важно: включите запись разговоров

Панель показывает записи только для звонков, у которых Asterisk фактически
сохранил файл. Включите Call Recording:
`Connectivity → Outbound/Inbound Routes → Additional Settings → Call Recording: Force`
(или на конкретных Extensions при точечном тесте).

Файлы должны лежать в `/var/spool/asterisk/monitor` (путь задаётся в
`.env`, переменная `RECORDINGS_DIR` — поменяйте, если у вас настроено иначе).

## Удаление

```bash
sudo ./install.sh --uninstall
```
Спросит, удалять ли MySQL-пользователя и папку `/opt/cdr-panel` с данными
(логины панели хранятся в `cdrpanel.db`, при удалении папки будут потеряны).

## Структура

- `app.py` — маршруты Flask (логин, список CDR, раздача записей)
- `cdr_query.py` — построение SQL-запроса, фильтры, классификация типа звонка
- `recordings.py` — потоковая раздача аудиофайлов вручную (не
  `send_from_directory` — на больших файлах эта связка с gunicorn(gthread)
  ранее в проекте отдавала пустое тело; см. заметку в коде)
- `auth.py` — логин/сессии/CSRF
- `db.py` — подключения к служебной SQLite и read-only к `asteriskcdrdb`
- `config.py` — настройки (переопределяются через `.env`, который создаёт
  install.sh)

## Известное ограничение текущей версии

Фильтр "Тип вызова" (входящий/исходящий/внутренний) применяется после
выборки страницы из БД — на больших объёмах данных с активным фильтром
страница может быть неполной. Для объёма этого проекта не критично; при
необходимости логику классификации можно перенести в SQL (`REGEXP` по
`src`/`dst`).
